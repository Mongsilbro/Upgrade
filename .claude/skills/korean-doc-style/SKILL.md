# 한국어 문서 문체

출처: [leeandev/stop-slop-ko](https://github.com/leeandev/stop-slop-ko) (`plugins/stop-slop-ko`, MIT, © 2026 leeandev). 요약·재작성했고 스캔 스크립트와 자동 실행 훅은 가져오지 않았다. `UPGRADES.md` 참조.

**내용·사실·숫자·근거·용어는 100% 보존하고, 어조·문장부호·상투구만 고친다.**

## 세 가지 모드

- **새로 쓸 때**: 처음부터 아래 신호를 쓰지 않는다. 같은 시리즈의 이전 문서(지난 회의록, 기존 양식)가 있으면 그 문체를 따른다. 없으면 보고서·회의록·표 = 개조식(명사형, 「~함/~됨」), 메일·안내문 = 「~합니다」.
- **다듬을 때**: 아래 A·B 신호만 고친다. **종결어미(「~함·~됨·~한다·~합니다」)는 바꾸지 않는다.**
- **기존 문서에 맞출 때**: 기준 문서의 종결, 문장 길이, 기호 사용, 용어를 먼저 정리하고 거기에 맞춘다. 종결을 바꾸는 것은 이 모드에서만 한다.

## 한국어 함정

개조식의 명사형 종결과 「~함/~됨」은 **한국 공문서의 정상 문체**다. 영어식으로 "능동태·짧은 서술문"으로 바꾸면 오히려 어색해진다. 한국어에서 AI 티가 나는 곳은 종결이 아니라 **문장부호·번역투·상투구**다. 요구사항·과제를 셋 나열한 것은 내용이니 건드리지 않는다.

## A. 문장부호

| 신호 | 고치는 법 |
|------|-----------|
| 문장 속 줄표 `—` | 쌍점 `:`, 괄호, 또는 문장 나누기 |
| 띄어 쓴 가운뎃점 ` · `으로 나열 | 쉼표나 `/` |
| 장식 `★`, 이모지 | 삭제(강조는 굵게) |
| 문장 속 `÷ = ×` | 말로 풀어 쓰기 |
| 조사 앞 공백(`"제시" 에`, `40,000 은`) | 붙이기 |
| 곧은·둥근 따옴표 혼용 | 문서 안에서 하나로 통일 |

`※`(주석), 표·도식의 `→`, 표의 `—`(해당 없음), 「성능·품질」처럼 붙여 쓴 가운뎃점 복합어는 정상이니 그대로 둔다.

## B. 번역투·상투구

| 신호 | 고치는 법 |
|------|-----------|
| 「~에 있어(서)」 | 빼거나 「~에서」 |
| 「~을 통하여」 남발 | 「~로」 |
| 「~되어지다」 이중 피동 | 「~되다」 |
| 「~라 할 수 있다」 | 단정 |
| 「~대비 …상이」 | 「~와 다름」 |
| 「제고·도출·확보함」을 겹친 명사화 | 풀어 쓰기 |
| 문장마다 같은 리듬의 3단 병렬 | 나누거나 변주(내용이 정말 셋이면 유지) |

## C. 서술형 글(리포트, 에세이, 칼럼, 블로그, 연설문 초안)

- 교훈형 마무리(「~의 중요성을 깨달았다」) → 원문에 실제로 바뀐 행동·사실이 있으면 그걸로 끝내고, 없으면 지운다.
- 「단순한 ~이 아닌 ~이다」 → 앞쪽 부정을 빼고 주장만.
- 명언·사전 정의로 시작 → 사실이나 장면으로 시작.
- 「정말·매우·굉장히·진정한」 → 지우거나, 원문에 숫자가 있으면 숫자로.
- 「~라고 생각한다」 반복 → 근거가 있으면 단정, 없으면 근거를 더하거나 지운다.
- 「또한·나아가·이처럼」으로 시작하는 문단 연속 → 첫 문장이 앞 문단과 이어지게.
- 「~해야 할 때다」 같은 일반론 결말 → 본문에서 나온 구체적 다음 행동으로.

## 지어내지 않기

- 새로 쓸 때 사실·수치·인용·출처를 만들지 않는다. 자료에 없으면 `[확인 필요: …]`로 남긴다.
- 회의록에 발언에 없던 결정·일정·담당자를 넣지 않는다(없으면 「미정」).
- 다듬을 때 문장을 지울 수는 있어도 새 주장이나 근거를 더하지 않는다.

## 확인

고친 뒤 원본과 비교해 **바뀐 곳이 문장부호·표현뿐인지**, 숫자·고유명사·조항 번호가 그대로인지 확인한다. 그리고 원래 쓴 사람의 말투로 읽히는지 본다. 더 매끄러워졌어도 말투가 사라졌으면 되돌린다.
