# 공무원 기획보고서

출처: [commetee12-source/gov-report-skill](https://github.com/commetee12-source/gov-report-skill) (MIT, © 2026 commetee12). 대통령비서실 「보고서 작성 매뉴얼」(2005) 요지와 현직 공무원이 확정한 실무 표기 규칙을 바탕으로 한 원본을 요약·재작성했다. DOCX 빌더·검증 스크립트는 가져오지 않았다. `UPGRADES.md` 참조.

## 원칙

1. **근거 있는 수치만.** 모든 판단과 대안에 출처·기준시점이 있는 수치를 붙인다. 거짓·추측·가공 데이터, 지어낸 출처는 쓰지 않는다.
2. **결재자 관점.** 결재자가 무엇을 결정해야 하는지 분명히 하고, 결재자가 다시 그 윗선에 보고할 수 있을 만큼 완결되게 쓴다.
3. **쉽게·간결하게·명확하게.** 어려운 용어는 풀어 쓰고, 영문 약자는 처음 나올 때 풀이한다.
4. **문제점과 개선방안은 1:1 대응.** 문제점 `1)~4)`와 개선방안 `1.~4.`의 번호를 맞추면 대응이 자명하다. 1:다 대응이면 사유를 적는다.

## 절차

### 1. 자료 분석
- 받은 파일을 모두 읽고 핵심 주제·수치를 뽑는다(한글 파일은 설치된 HWP/HWPX 스킬로).
- 파일 간 연결고리(공통 주제, 인과, 시간 흐름)를 찾는다. **연결고리 없는 자료는 빼고, 뺀 이유를 알린다.**
- 주제만 받았으면 공식 통계·기관 자료를 검색해 근거를 모은다.
- 분석 결과와 보고서 방향을 먼저 보여 주고 확인받는다. 출력 형식(마크다운 / 한글(HWPX) / 워드)도 정하지 않았으면 묻는다.

### 2. 구조
```
Ⅰ. 추진 배경        (필요성·긴급성·근거·경과)
Ⅱ. 현황 및 문제점    (현황 = 사실, 문제점 = 원인. 섞지 않는다)
Ⅲ. 목표 및 추진방향  ※ 원자료에 확정된 기한·수치가 있을 때만
Ⅳ. 개선방안
Ⅴ. 세부 추진계획    (일정·예산·인력·협조사항)
Ⅵ. 장애 및 극복방안  ※ 실제로 식별된 리스크가 있을 때만
Ⅶ. 기대 효과        (정량 + 정성)
붙임 1. 2. …        (건의사항·참고자료, 각각 새 쪽에서 시작)
```
- 7개 항목은 **체크리스트가 아니라 선택지**다. 칸을 채우려고 목표·리스크를 지어내지 말고, 근거가 없으면 章을 빼고 번호를 다시 매긴다.
- 「건의 사항」은 본문 章이 아니라 붙임으로 뺀다.

### 3. 작성 전 점검 — 여섯 줄 이야기
무슨 일이 있었나 → 왜 → 그대로 두면 어떻게 되나 → 무엇을 해야 하나 → 무엇이 바뀌나 → 지금 할 일은. 여섯 줄이 자연스럽게 이어지지 않으면 논리에 구멍이 있다.

### 4. 작성
- **현황**: 바람직하지 않은 상태를 수치로(목표 미달, 하락 추세, 민원 증가). 가능하면 3년 이상 시계열이나 타 기관 비교를 함께.
- **문제점**: 근본 원인을 시급성×중요성 순으로. 항목 간 중복·누락이 없게 묶는다.
- **목표**: 구체적·측정 가능·달성 가능·현실적·기한 명시. 예: 「처리기간 8.2일(2024) → 5.0일(2026)」.
- **기대 효과**: 개선방안의 수치와 일치하게, 정량·정성을 나눠서.
- 수치는 차트·표로 시각화한다(차트는 한글 글꼴이 깨지지 않는지 확인).

## 표기 규칙 (실무 우선)

- **번호 체계**: `Ⅰ. → 1. → 1) → ①`. `가. 나. 다.`는 쓰지 않는다. 짧은 보고서는 `□ ○ - ·` 기호만 써도 된다.
- **넣지 않는 것**:
  - 「보고 개요」「보고의 목적」「작성 경위」 — 「Ⅰ. 추진 배경」으로 바로 시작한다. 경과가 중요하면 추진 배경 안의 `□ 추진 경과`에 날짜와 함께 넣는다.
  - 작성 지침·메타 문장 — "문제점과 1:1로 대응한다", "아래는 우선순위다". **지워도 결재자가 잃는 정보가 없으면 메타 문장**이다.
  - 기법 이름 — `1. 목표 (SMART)` ✗ → `1. 목표` ✓. MECE·로직트리 등도 같다.
  - 라벨 접두어 — `문제점 ① …` ✗ → `1) …` ✓.
- **쪽번호 필수.** 목차는 한 쪽 안에 들어가게 한다. 큰 제목 아래 밑줄은 넣지 않는다.
- **파일명**: `[기획보고서]_핵심어_핵심어.확장자` (사용자가 다른 규칙을 쓰면 그것을 따른다).

## 문체

- **기본(하이브리드)**: 분석·논증·맥락 설명은 서술형 단락, 수치·과제 목록·표·시사점은 개조식.
  - 서술형: 한 문장 100자 안팎, 한 단락 3~5문장, 현재형. 평가는 「~로 분석된다·~로 판단된다」.
  - 개조식: 명사형 종결, 수치를 구체적으로(「증가」 → 「8.7%p 증가」), 전후 비교는 병기(「82.3% → 71.5%」).
  - 한 단락 안에서 두 문체를 섞지 않는다.
- **「개조식으로」「기안용」「공문 형식」을 요청하면** 전부 개조식으로 쓴다.
- 피할 것: 「시대적 요구에 부응」 같은 추상적 배경, 「매우 심각한」 같은 수식어, 「~함에 있어서」「~로 인하여」 같은 군더더기, 한 문장에 여러 메시지, 주어 없는 「검토함」.
- 문장 다듬기는 `korean-doc-style` 스킬을 함께 쓴다.

## 전달할 때 — 보완 항목 자기보고

보고서 본문에는 표시하지 않고, **답변 메시지에 따로** 알린다.

```
## 검토 시 확인이 필요할 수 있는 부분
원자료에 없어 보고서 구조상 보완한 항목입니다. 실제 보고 전에 사실관계 확인이 필요합니다.
- **정량 목표치**(Ⅲ-1): ○○ 권고치와 ○○ 사례를 참고한 제안치. 내부 협의 후 조정 필요.
- **소요 예산**(Ⅴ-2): 원자료에 없어 「기존 예산 활용」으로 보수적으로 기재.
- **근거 조항**(Ⅰ): 조항 번호는 국가법령정보센터에서 확인 필요.
```

- 대상: 추정한 목표치, 일반적으로 기재한 법령 조항·예산·인력, 논리상 덧붙인 비전·정성 효과.
- 대상 아님: 표지·목차 등 형식, 문장 다듬기, 원자료 수치를 그대로 그린 차트.
- 보통 3~6개. 7개 항목 중 절반 이상을 보완해야 한다면, 쓰기 전에 원자료가 부족하다고 알리고 추가 자료를 요청한다.
- **허용되는 보완과 금지되는 가공의 구분**: 「관련 부서 협의 추진」(일반 기재)은 되고, 「○○과 ○○○ 과장 협의 완료」(허구)는 안 된다. 「기존 예산 활용」은 되고, 「예산 5억 원 확보」(허구)는 안 된다.

## 결재자 시각 최종 점검

| 영역 | 질문 |
|------|------|
| 명분 | 왜 지금 해야 하나? |
| 근거 | 모든 수치에 출처·기준시점이 있나? |
| 논리 | 현황 → 문제점 → 개선방안이 이어지나? |
| 실행 | 누가·언제·무엇을·어떻게? |
| 자원 | 예산·인력이 현실적인가? |
| 효과 | 무엇이 바뀌고, 측정 가능한가? |
| 결정 | 결재자가 결정할 사항이 분명한가? |
| 일관성 | 배경·현황·목표·효과의 수치와 용어가 서로 맞나? |

하나라도 바로 답할 수 없으면 그 부분을 다시 쓴다.
